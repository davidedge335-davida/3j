# 五个领域 · 三维沙盘（代码包）

信中伟业官网「解决方案」板块用的实时三维沙盘。整套只有一个代码文件 `sol3d.js`（约 1700 行，已逐节写了中文注释），依赖 three.js r170。

## 怎么打开

浏览器不允许双击直接打开 ES 模块，需要起一个本地服务器：

```
cd sol3d-code
python3 -m http.server 8000
```

然后访问 http://localhost:8000/ 。点下面的按钮或按 ← → 键切换五个领域。

在浏览器控制台里还可以试：

- `__sol.goTo(3)`：切到金融保险
- `__sol._hold(1.5)`：定格在政务切到教育的一半，可以看扫光和土层是怎么换的

## 看代码前先知道的三件事

1. **坐标**：台面是半径 1 的圆，圆心在原点。x 向右，z 朝向镜头（屏幕下方），y 向上。所以布局里的数字都在 -1 ~ 1 之间：z 为负是台面远处（画面上方），z 为正是近处（画面下方）。一层楼高 0.021，约 3.5 米，1 个单位约 170 米。
2. **颜色**：代码里 `[r, g, b]` 形式的颜色是三维渲染用的线性空间，数值看起来比网页颜色小，比如 `[0.5, 0.49, 0.47]` 实际显示是浅灰。地貌图里写的 `'#xxxxxx'` 就是普通网页颜色。
3. **随机是固定的**：随机数用固定种子，每次打开，树的位置、车的颜色、哪些窗亮灯都一样。对着截图提的意见，打开后看到的是同一个画面。

## 常见修改，去哪里改

| 想改的 | 位置 | 怎么改 |
|---|---|---|
| 某栋楼的位置、高度、样式 | §11 对应领域里的 `add(D, tower({...}), null, x, z)` | 改 x、z 挪位置；改 `h` 改高度；`style` 换窗型（0 普通窗、1 玻璃幕墙、3 竖长窗）；`col` 换墙面色 |
| 车多一点或少一点 | §11 各领域开头的道路定义 | `n` = 每条车道的车数，`speed` = 车速 |
| 人多一点或少一点 | §11 各领域末尾的 `crowd(...)` 那几行 | `walkPath(路线, 人数)`、`wander(x, z, 范围, 人数)` 里改人数 |
| 草地、广场、路面的颜色 | §11 各领域 `terrain(t => {...})` 里 | `t.grass(区域, '#颜色')`、`t.paving(区域, '#颜色', …)` 里的网页颜色 |
| 台座侧面的土层 | §4 `strata()` | 每种土的颜色和每层的深度 |
| 夜里亮灯的窗户多少 | §5 `pOn = clamp(0.10 + 0.62 * zone …)` 那一行 | 0.10 调大，亮灯的窗更多 |
| 切换速度 | `create(canvas, THREE, { duration: 1.6 })` | 每切一格的秒数 |
| 镜头俯角、远近 | §14 `camBase` 和 `camBase.dist` 的公式 | `el` 是俯角（弧度），距离公式里的 1.38 调大镜头更远 |
| 转台摆动幅度 | §16 `turntable.rotation.y = … Math.sin(t * 0.07) * 0.32 …` | 0.32 是摆幅（弧度），0.07 是快慢 |
| 整体亮度、光晕 | §13 `final` 的 `uExp`（曝光）和 `uBloom`（泛光） | 在 `final: pass(...)` 后面的参数里 |
| 景深（前后虚化）强弱 | §13 `renderFrame()` 里 `ap = 16 * H / 900` | 16 调小虚化变弱；或 `create(…, { dof: false })` 直接关掉 |
| 领域色（切换扫光的颜色） | 文件开头 `DOMAINS` 的 `accent` | `[r, g, b]` 0~1 |

## 性能

在测试里每帧 65~180 次绘制，7 万~22 万个三角形。按这个量级，普通笔记本集显和近几年的手机一般都能流畅跑，不过还没在真机上测过帧率。另外有四个省资源的措施：

- 画布滚出屏幕就停止渲染
- 渲染像素数封顶约 220 万
- 连续卡顿时自动降分辨率，流畅后再慢慢升回去
- 手机上地貌贴图用 1024²（桌面 2048²）

浏览器不支持 WebGL2 时，这个演示页显示一行提示。接进官网时，计划让这类浏览器继续显示原来的帧序列动画。
